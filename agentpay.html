02.1 THE PAYMENT BARRIER

Agents can reason.
Payments still need boundaries.

The normal payment interface only answers whether the transaction is completed; AgentPay must also answer who the agent represents, why it has the authority to act, which version of the policy is adopted, and who gives final approval.

01 / AUTHORITY

Agent can trigger.
User cannot authenticate.

In the absence of identity, delegation, and quotas, automation can misinterpret a single authorization as a permanent permission.

02 / SETTLEMENT

Service already exists.
The agent cannot pay securely.

Agent requires a controlled settlement track that can be rejected, paused, and upgraded for manual processing.

03 / EVIDENCE

Task has been executed.
The result cannot be proven.

Transaction hashes can only prove network actions and cannot independently explain the complete authorization and decision-making process.

02.2 CONTROLLED TRANSACTION PROTOCOL

Evaluate first.
Move value second.

Agent only submits structured intents. Authorization, quotation, risk, manual confirmation, on-chain execution and receipt each remain independent, and any step can be rejected or stopped.

02.3 AI TASK RECEIPT

Beyond the transaction hash,
preserve decision evidence.

The receipt layer binds task context to on-chain actions. The public chain only carries necessary summaries and references, and sensitive prompt words, corporate data, private keys and complete output remain in a controlled environment.
